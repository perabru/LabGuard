LabGuard 2.1.0 · Comece por aqui

Seu laboratório, mais organizado.

O LabGuard começa em observação local da rede, sem aplicar bloqueios automaticamente. Dados fictícios aparecem somente quando você escolhe a demonstração.

1. Abra e observe

Clique em Identificar minha rede. O cartão O que foi identificado mostra fonte, estado, endereços com evidências e próximo passo. Um endereço observado não comprova presença atual; a cobertura pode ser parcial. Dados antigos e identidades conflitantes ficam indicados antes de uma ação.

2. Conecte o equipamento

Configure uma conexão direta com um modelo compatível. O desktop não exige um gateway Linux adicional. O adaptador direto usa RouterOS 7 com REST por HTTPS, serviço www-ssl e certificado TLS validável. Informe endereço, porta (443 por padrão), usuário e senha de uma conta autorizada. Se necessário, selecione o arquivo da CA da rede; preserve a validação TLS.

As capacidades variam por modelo e integração: consulte os recursos oferecidos antes de aplicar regras. A instalação do painel não cria compatibilidade universal com roteadores ou switches.

3. Valide uma ação

Comece por uma estação ou equipamento de teste. O alcance do filtro depende do caminho do tráfego e do tratamento das consultas DNS. VPN, DNS externo/criptografado, NAT intermediário e MAC privado podem limitar o controle e a identificação.

4. Escolha a edição

O desktop está disponível para Windows e Linux e inclui o runtime Python. RouterOS direto usa HTTPS. As integrações SSH opcionais usam o cliente OpenSSH do sistema. Os pacotes opcionais de servidor oferecem painel web local, tokens e serviço de inicialização automática; não são necessários para usar a conexão direta do desktop.

Se a identificação falhar

  1. Em Início, clique Não identificou? Ver passo a passo.
  2. Confira o sintoma e siga as etapas de leitura indicadas para Windows ou Linux.
  3. Use Atualizar consulta para conferir o resultado. Dados parciais não ativam bloqueios.
  4. Se a marca ou o modelo continuar desconhecido, confira a etiqueta e o painel do equipamento com a TI. Não envie senhas nem tokens.

A leitura Linux prefere o comando ip do pacote iproute2; o Debian declara essa dependência. Quando o método principal falha, a aplicação tenta fontes locais alternativas e informa seus limites. Não instala ferramentas nem gera tráfego para preencher a lista. Abrir o passo a passo completo.

Consultas DNS não comprovam visitas nem revelam conteúdo HTTPS. O perfil de IA trata os domínios cadastrados; aplicações locais e serviços integrados exigem controles complementares.

Para remover no Windows, use Configurações → Aplicativos → LabGuard → Desinstalar. No Debian/Ubuntu, use sudo apt remove labguard. Remover o aplicativo não desfaz políticas já aplicadas em equipamentos externos.
